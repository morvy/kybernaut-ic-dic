# 2.0 structure: from includes/*.php to namespaced classes

Status: done, c6eccdc..c07e57e plus step 7 (docs, `woolab_icdic_suggest_enabled()`). The
tree and API below are as built; the notes under "As built" list where it differs
from the proposal.

## Goals

1. Every field check is its own class behind one interface, listed in a filter, so a
   store (e.g. a Polish one) adds, replaces or switches off a check without touching
   the rest.
2. The registers (ARES, Finančná správa, VIES) sit behind interfaces too, so a store can
   plug in its own (GUS/REGON for Poland, NAV for Hungary).
3. PSR-4 classes under `KybernautIcDic\`, autoloaded by Composer (already shipped:
   `composer install --no-dev` in create-build.yml, `vendor/autoload.php` in the main file).
4. Nothing a store relies on changes: option names, order/user meta keys, block field
   ids (`kybernaut/*`), REST routes, script handles, every `woolab_icdic_*` filter, and the
   public `woolab_icdic_*` functions (kept as thin wrappers in `functions.php`).

## The check API

```php
namespace KybernautIcDic\Validation;

interface Check {
	public function id(): string;                         // 'vat_id_vies'
	public function applies( Context $context ): bool;    // country, field present, setting on
	public function run( Context $context, Result $result ): void;
}
```

Checks share data without depending on their order:

- **Lookups are memoised in the Context.** `$context->company( $ico )`,
  `tax_id( $dic )` and `vat_id( $number )` ask the country's services once per request; BusinessIdRegistry,
  TaxIdRegistry (DIČ belongs to the IČO) and IcDphVerify (IČ DPH tied to the same IČO, VAT
  groups) all read the same answer.
- **Exclusive routes, stated in applies().** Where the old validator chained
  `elseif`, each check's applies() states the condition (Checks\TaxId::route() picks
  the one route of a DIČ: domestic tax number, VIES, CZ format or SK); the default
  order reproduces the old error order, which ValidationTest pins.
- **Facts for what comes after.** The Result also records what was verified
  (`vat_state`, `check_fail_ignored`), which VatExempt reads instead of asking VIES again.

Filters (both checkouts run the same Validator):

| Filter | For |
|---|---|
| `woolab_icdic_checks` ( Check[] $checks, Context ) | add, remove, reorder, replace checks, keyed by id |
| `woolab_icdic_check_applies` ( bool, Check, Context ) | switch one check off for a country or a case |
| `woolab_icdic_check_result` ( Result, Check, Context ) | adjust what one check found |
| `woolab_icdic_validation_result` ( Result, Context ) | the final errors / notices |
| `woolab_icdic_services` ( array $map ) | country => feature => services: replace ARES, Finančná správa or VIES, or add a country |

A Polish store, e.g. NIP checked against the Polish VAT whitelist instead of VIES:

```php
add_filter( 'woolab_icdic_checks', function ( array $checks ) {
	$checks['vat_id_vies'] = new My\Shop\WhitelistNip( $checks['vat_id_vies'] ); // PL → own, rest → VIES
	return $checks;
} );
```

## National services (PL, HU, …)

A store plugs in its country's service with woolab_icdic_services, and the checkout
then works as for CZ and SK:

- Service::name() ("ARES", "Finančná správa", "GUS") for the messages.
- Autofill for a country = a company_search service is assigned (CZ / SK: their
  autofill settings decide that, as now).
- BusinessIdRegistry compares the entered company with the service's for any
  country with autofill; the mismatch message names the service (one new string,
  translated in all four locales).
- The script data lists, per country, which features have a service (lookup,
  search); public.js and blocks.js (step 6) look up and search for any such
  country, the block checkout's IČO field included (not only the home countries).
- readme FAQ "Your own national service": a complete Polish example.

## As built

- Registry\ (4f2800d) became Services\ (46caf74): one Service per external service,
  a method per feature, assigned per country with woolab_icdic_services.
- The checks are named after the field they check (IcDph* for the SK IČ DPH); the
  VAT format check is part of VatIdVies; TaxId is the DIČ route helper, not a check.
- AbstractCheck and SkLists are additions; Fields\Definitions and shared/labels.js
  were not needed; CSS keeps style.css and lookup.css apart.
- Hook callbacks are class methods: remove_action() with a 1.x function name no
  longer matches (readme changelog). Compat\FluidCheckout is still not hooked: call
  its register().

## How it moved

One area per commit, behaviour unchanged, unit tests + both Playground stacks green
after each:

1. composer PSR-4 + Plugin bootstrap; move Logger, Options, Flags, Checksum (pure).
2. Validation: Check / Context / Result / Validator; one check class per branch, the
   existing ValidationTest cases run against the Validator unchanged, plus a test per
   check and per filter.
3. Registries behind the interfaces (Ares, Vies, Finančná správa).
4. Checkout\Classic, Checkout\Blocks, VatExempt, Errors.
5. Order, Rest, Settings, Assets, Compat.
6. JS/CSS: resources/ + @wordpress/scripts, shared modules.
7. functions.php wrappers for the public functions; PHPCS / PHPStan / Rector
   pass on the whole codebase; docs (CLAUDE.md, readme FAQ "Custom checks").
